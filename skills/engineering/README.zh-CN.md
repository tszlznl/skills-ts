# Engineering（工程）

我每天用于代码工作的技能（skills）。

- **[diagnose](./diagnose/SKILL.zh-CN.md)** — 面向棘手 bug 与性能回归（performance regressions）的纪律化诊断循环：复现（reproduce）→ 最小化（minimise）→ 假设（hypothesise）→ 埋点/观测（instrument）→ 修复（fix）→ 回归测试（regression-test）。
- **[grill-with-docs](./grill-with-docs/SKILL.zh-CN.md)** — 以现有领域模型（domain model）为基准拷问你的计划，打磨术语，并内联更新 `CONTEXT.md` 与 ADR（Architecture Decision Record）。
- **[triage](./triage/SKILL.zh-CN.md)** — 通过一个“分诊角色（triage role）”状态机，对问题（issues）进行分诊。
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.zh-CN.md)** — 基于 `CONTEXT.md` 中的领域语言（domain language）以及 `docs/adr/` 里的决策，寻找代码库中“加深（deepening）”的机会。
- **[setup-matt-pocock-skills](./setup-matt-pocock-skills/SKILL.zh-CN.md)** — 为每个仓库（repo）搭建配置（问题跟踪器、分诊标签词汇、领域文档布局），供其他工程技能使用。
- **[tdd](./tdd/SKILL.zh-CN.md)** — 采用红-绿-重构（red-green-refactor）循环的测试驱动开发（test-driven development）。一次只构建一个垂直切片（vertical slice）的特性，或修复一个垂直切片的 bug。
- **[to-issues](./to-issues/SKILL.zh-CN.md)** — 把任何计划（plan）、规格（spec）或 PRD（Product Requirements Document）拆成可独立领取（independently-grabbable）的 GitHub（GitHub）Issue（issue），采用垂直切片（vertical slices）。
- **[to-prd](./to-prd/SKILL.zh-CN.md)** — 把当前对话上下文（conversation context）整理成 PRD，并作为 GitHub（GitHub）Issue 提交。
- **[zoom-out](./zoom-out/SKILL.zh-CN.md)** — 让智能体“拉远视角（zoom out）”，为不熟悉的代码区域提供更广的上下文或更高层的视角。
- **[prototype](./prototype/SKILL.zh-CN.md)** — 构建一次性原型（throwaway prototype）来补全设计：可以是用于状态/业务逻辑问题的可运行终端应用（terminal app），也可以是多个差异巨大的 UI（User Interface）方案，通过一个路由（route）进行切换。
